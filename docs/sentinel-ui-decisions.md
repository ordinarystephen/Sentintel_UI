## Keeping

**Data model nuances (2026-08-28)**
- There is no review "type": annual/thematic/target distinctions do not exist. A review is a review; only the supporting documentation differs, and that is not a tag, filter, or header label. The review header is borrower name + ID only (e.g. "Veyland US Holdco LLC · RXM-6430").
- One deliverable, one export: the rendered Word review, labeled **"Export Review"**. No Excel export.
- **Line of business** is a real filter dimension (IB Lending / Wealth Management / Counterparty Credit Risk) on the All-reviews list and the Documents search.
- Every extracted or input workpaper item carries an inline **confidence score** (quiet mono chip, e.g. `conf 94%`; amber below the floor, paired with the review-required flag — the same threshold the export enforces).

**Structure and navigation**
- GitHub-modeled fixed left rail: Home, My reviews, All reviews, Documents, Policy library (candidate). Collapse control at the foot; collapses to an icon strip. Rail never scrolls with content; only the main working area scrolls.
- Contextual "current review" zone under the app nav when inside a review; section numbers act as icons in the collapsed strip.
- Review page order: the story/summary first, then a collapsible NEEDS YOUR ATTENTION block (count badge visible when collapsed), then the workpaper.
- Sticky borrower bar: borrower name + ID + Export Review pinned while the workpaper scrolls.
- **Areas of assessment** (added 2026-09-09 from a real workpaper example): the management-summary verdict layer — each major review topic (transaction structure/underwriting, repayment capacity primary/secondary, portfolio management, regulatory classification, PD, LGD, traded products) with a rating disposition (satisfactory / unsatisfactory / n-a / pending) and a reason narrative. Sits between the attention block and the workpaper; the whole zone is collapsible (like the attention block) with the pending count remaining visible on the collapsed header, and each area row collapses individually. Structural to every review (clarified 2026-09-09): all reviews carry the zone — completed reviews fully rated, read-only reviews without action buttons; a missing-areas state is a data-integrity guard, never an expected state. Ratings are analyst dispositions (AI-suggested once reasoning is live; advocate/dissent feed contested ones), recorded to the review record; a pending area names its blocker and deep-links to the section; the exported review opens with this table (screen = deliverable).
- **Entity reference data, sparingly** (added 2026-09-09): upstream credit-system facts (credit officer, PD/PD CRR, facility, accrual status) and CRR-internal designations (reference number, portfolio-bucket industry) behind one collapsed disclosure under the sub line, each value marked by origin, upstream values carrying an as-of snapshot date. Not rendered when feeds are absent. Prepared-by/reviewed-by deliberately omitted for MVP (owner is already in the record; RIC sign-off is stage 2).
- Inline collapsible workpaper: one document flow, serif section titles on hairline rules. (Supersedes the section card grid and the separate drill-in screen.)
- **Canonical section titles** (corrected 2026-09-09; the earlier six were indicative POC-era names): 1 Borrower / Counterparty & Relationship Overview · 2 Financials · 3 Underwriting & Documentation · 4 Portfolio Management · 5 Risk Rating Accuracy · 6 Trading Activity & Exposure Analysis. There is no "Recommendation" section — adjudication lives in the areas of assessment. Assessment supporting-section mappings: underwriting → §3, repayment areas → §2, portfolio management → §4, USRC/PD/LGD → §5, traded products → §6.
- Attention items and rail section numbers deep-link: expand the target section and scroll to it.
- Right context rail on the review screen: follows the selected workpaper item, collapsible, four tabs —
  - *Why*: how the content got here (template concept → resolution tier → source page → flags) plus the policies/standards applied, with links.
  - *Respond*: free-text response to Sentinel with send-and-re-run; mark verified; clear content as Not applicable or Incorrect. Cleared content stays **on screen**, struck through with the rationale beside it (the QC trail is visible while working); the **exported review simply renders without it**. Nothing silently deleted.
  - *Debate*: advocate and dissent agent positions with citations; advisory only, analyst disposition decides; both positions ride into the review record.
  - *Prior*: "what changed since last review" deltas when the borrower has prior reviews (distinct from the story timeline, which compares documents within this run). Links to the prior review.
- Landing: files-only upload (no metadata form) + optional context/questions text zone; extraction settings demoted behind an "Advanced" link; hero + recent reviews below.
- Processing: calm/ambient (one line, one bar, no pipeline anatomy), Cancel present, persistence promised out loud; a new review appears as "New review — reading…" until the borrower is detected, then renames itself.
- Reviews screen: My/All tabs; All = team-wide read-only view with search + filters (line of business, owner, period) and absolute timestamps — built for hundreds of reviews. Repeat coverage is first-class: the same borrower can appear multiple times (material-change re-reviews), with a repeat-count chip.
- Documents screen, two states (revised 2026-08-31 from Steve's test pass): **browse** shows clean rows only — filename, extraction status, LOB, date; no preview text. Selecting a row reveals its actions: Preview extracted text, Download original, and "Used in [borrower] review →" when applicable (post-select option list still open). **Search** (query active) shows matched passages with terms marked — evidence of the match, not decoration. Preview opens a modal of the extracted text organized by the document's own sections with page ranges; not-yet-extracted documents show the preview action disabled. Badge semantics settled 2026-09-09 in the repo's favor: slate "not yet extracted" (extraction is not a user action on this screen, so amber's call-to-action signal would mislead); mockup synced to match.

**Visual language**
- Warm stone palette as default (ink #1c1917 family), replacing pure zinc. Color stays reserved for status.
- Serif (New York/Georgia) promoted to the names of things: borrower, screen titles, workpaper section titles. UI labels stay sans. Serif italic remains the evidence voice.
- Quiet motion: ~150ms stagger settle on screen content, easing accordions, neutral one-time flash on deep-link targets. All disabled under prefers-reduced-motion. Calm, never bouncy.
- Theme selection on one token contract: Stone (default) and Cobalt (Steve's navy palette: primary #19398d, dark navy sidebar #001B3C, cool light ground #f3f5fb), each with a real dark variant; moon toggle flips dark within the chosen family.
- Light-theme contrast fix (ratified 2026-08-28): `--faint` darkened to `#8a837b` in Stone light (also `--rail-fg-muted`) and `#76839d` in Cobalt light, bringing micro-labels, timestamps, and rail glyphs to ≥3:1. Dark themes unchanged (already passing). Mockup and repo tokens both updated.

**Fictional-data hygiene** (2026-09-09): all demo/fixture names are vetted-fictional — collision-checked against real companies. Canonical set: Veyland US Holdco LLC (protagonist), Ambervale Foods Group, Seldwyn Marine Finance, Northgale Health Partners, Farrowdale Logistics, Verloway AgriChem; sponsor Bramhurst Capital. Earlier names (Meridian/Atlas/Halcyon/Beacon/Crestline/Verdant/Bellwether) were retired for plausible real-company collisions. Generated review rows must use coined, non-colliding names; README and fixtures carry an "all names fictional; any resemblance coincidental" note. Policy citations use the illustrative ProcMan-DEMO id — real internal document numbers never appear with illustrative text.

**Principles**
- Screen = deliverable: whatever the exported DOCX flags (e.g. REVIEW REQUIRED on low-OCR values), the screen shows in place. The screen may additionally show working state (struck cleared content, dispositions) that the export omits — the export is always the clean rendered document.
- Provenance everywhere: page number on the evidence quote line; source modal kept (evidence one click away, section views stay clean).
- Explainability is a surface, not a tooltip: every AI output can show its reasoning chain and the standards it was held to (right rail "Why").
- Honest seams: "reasoning stubbed" labeled, retrieved-snippets disclosure preserved; assessment factors live inside the section they assess.
- Flags are actionable: confidence inline, dismissable, linked to their section.
- Read-only parsed content + dispositionable findings (mark reviewed with note, un-review, note editing, clear-with-reason) is the MVP edit boundary.

## Ratified — build round 1 (2026-08-28)

Decisions from the Phase 0–6 build review, now settled:
- "Send & re-run" scope: the single selected item. The analyst's text records as a `responded` disposition and drives the re-run.
- Clear rationale: a required one-line note field in the UI for both Not applicable and Incorrect. UI validation is NOT the enforcement point — the handoff docs must state that the server enforces a substantive rationale (more than the category label).
- Read-only (non-owner) reviews: Prior tab visible, Export Review allowed; dispositions and clearing hidden.
- Line of business: the review is authoritative; documents carry a denormalized copy for search.
- `DebatePosition` contract frozen as `{ itemId, stance, text, citations[] }` plus a timestamp (and run id) added before the dev team builds the producer.
- Ratified as built: Tailwind v4; `--overlay` token; `ReviewStatus` gains `failed | cancelled`; `getPriorDeltas` returns `{ priorReviewId, priorDate, deltas }`; real advanced search (quoted phrases, `-exclusions`); desktop-only below 760px accepted as a documented known limitation; docs screenshots stay in git; spec lives at `docs/build-spec.md`.
- Demo identity: `me()` displays "Costello, Stephen"; production identity comes from the firm's credential management system ("Last, First" display format).
- Developer environment: internal Nexus package repository, configured via environment variables (`.npmrc`); dev team's first task is re-locking dependencies against Nexus. Assume evergreen Chrome/Edge, Node LTS.

## Ratified — suite round (2026-09-17)

- **Sentinel is a suite with three applications**: CRR (Credit Risk Review — the app built so far), ERM (Enterprise Risk Management; may be renamed), and Vantage (P&C). All three run on the shared platform; ERM and Vantage are "In design."
- **Suite landing page** (`design/sentinel-suite-landing.html`, concept r4): serif "Sentinel" wordmark top-left, no eyebrow, no tagline, no hero — literally the application cards, vertically centered. Wide stacked cards (not tiles, not tabs): serif app name + full name, single-line description, CRR gets the primary Open button, in-design apps get a quiet chip and no button. UBS logo will be added later (top bar, right edge) — off for now.
- **Card descriptions are single-line, Steve-draft, wordsmithing later** (live in `strings.ts`): CRR "Deep-dive credit review files, purpose-built for CRR." / ERM "Portfolio-level insights and analysis." / Vantage "Generic document extraction and insights."
- **Tabs rejected for app switching** — permanent chrome for a rare action, and they break under single-app entitlements (dead tabs or a one-tab bar). Instead: **entitlement routing** — one entitlement lands you straight in your app (no landing, no extra click); two or more get the landing once, then last-used app, with the masthead brand as switcher ("Sentinel · CRR ▾" → entitled apps + "All applications"). The landing page is the switcher's full-page form, not a toll booth.
- **Right context rail is drag-resizable** (Steve's pick over two-state toggle/overlay): handle on the rail's left edge, min 260 / max 560 / default 312, double-click resets, width persists (`sentinel.ctxWidth`), keyboard-accessible separator. At ≥420px the rail is a reading pane: content type steps up and Debate shows advocate/dissent side by side.

## Ratified — amend evidence round (2026-09-17)

- **Add document (amend evidence) in the borrower bar**: reviews aren't locked to their opening documents. "Add document" (outline, left of Export Review — the export stays the bar's only primary) opens a modal with two paths: upload new, or select from the repository (scoped to documents on system for this borrower not yet in the review). A **required** rationale field — "Why is this document being added?" — is recorded in the review's evidence log. On add, the evidence set gains the document with an amended-origin tag, and impacted checks re-run in place; no bounce to the processing screen.
- **Evidence manifest**: "Documents in this review" is a quiet disclosure under the ratings line, same pattern as Reference data. The summary answers at a glance (count + run status); rows carry filename, type, date, origin chip ("opening set" vs amber "added mid-review · time"), a Preview into the extracted text, and — for mid-review additions — the reviewer's why in the evidence-log voice. The old standalone "Run completed" line folded into the manifest summary.
- **Search keys are borrower/counterparty name (ultimate parent or partner name) and RXM** — the two things reviewers actually search. All document search areas (reviews list, Documents screen, add-document modal) lead with them; the Documents screen keeps full-text passage search as an explicitly secondary capability ("— or any keyword"). The borrower ID scheme is **RXM** (fixtures sweep from the CL format; e.g. RXM-6430).
## Ratified — ERM application round (2026-09-18)

- **ERM ships as the second live application**, speaking the suite's three-beat arc: start → processing → results. The monitor is a *result*, not a home. Registry status flips to active; the landing card gets its Open button; the masthead switcher navigates.
- **Start screen**: the question (free-text prompt + saved question-set select, combinable), the documents (optional — upload or repository picker; empty means run on the population), and **the population** — labeled dropdowns (Portfolio / Sub-portfolio / Region / As-of) whose *shape* is ratified while the list vocabulary is a deliberate placeholder; a scope-preview line resolves before Go. Population scope and explicit documents union into one run.
- **Processing**: staged honest steps (population resolved → index current → running questions → computing), Cancel run, and leave-and-it-lands-in-Runs.
- **Results**: a Summary area opens the screen — question-set chip, counts of *answers* by grade, the headline attention line — and the **population accounts for itself**: a disclosure answering "why these borrowers," with named exclusion reasons and the indeterminate (insufficient look-through) class reported, never silently defaulted. Exports ride the top (Excel-vs-Word ruling still open). Scroll-to-top at the bottom.
- **RAG is out** until amber-vs-green has a landed definition. **Grades belong to answers, never rows**: each answer is **stated** (a quote passes the entailment check) / **derived** (computed from stated inputs, derivation shown) / **unsupported** (nothing grounds it) — a decision table, no composite scores, no percentages; retrieval similarity retrieves and never grades. Rows carry only an amber flag count (CRR's attention-badge idiom). Whether "derived" is acceptable per field is question-set configuration. Cells: derived = dotted underline; unsupported = amber em-dash.
- **Flexible surface**: columns derive from the run's question set (identity columns pinned, "N of M shown", column picker TBD); the inline row expansion always shows every answer with grade + confidence chips; **by borrower and by question are two cuts of the same answer store**. Default sort most-flags-first; column sorting is pair-aware.
- **Runs are records**: every run (completed, cancelled, failed) is a frozen revisitable object with its population accounting and results as of its moment.
- **Documents (ERM lens)**: the shared repository grouped by borrower — collapsible groups, 3 documents visible then scroll, name/RXM search, in-scope chips, and both faces of a document viewable in-UI: the extraction and the raw pages.
- **Row unit stays per borrower** (deliberately not re-litigated this round; the cross-document disagreement rule remains open).
